# Gate scripts and hooks

Charter: repository gates, renderers, orchestration compilers, and hook behavior. Excludes workflow scheduling and eval fixtures.

The default posture is fail closed. Usage errors, malformed configuration, drifted generated output, untrusted documentation records, and invalid receipts fail. Process-risk advisories remain explicit exceptions. Atlas ambiguity is fail-safe: the checker calls a section stale rather than treating uncertain judgment as current. Digest-backed sections bind exact scopes, the staged index, and the index-to-worktree delta; commit pins remain diagnostic and legacy-compatible.

Model judgment no longer depends on repository-hosted review workflows. `local-review-gate.mjs` binds a clean feature branch, base, HEAD, binary diff, changed paths, two independent report identities, and a hash-chained receipt set. Ignored authority outputs cannot portably alias tracked Git paths. Physical identity retains lossless device and inode values on Windows. A shared index guard rejects assume-unchanged, skip-worktree, and submodule ambiguity before either local review or judgment planning reads worktree bytes. Publication verifies live remote base and feature refs and binds the destination repository to that same remote. `judgment-evals.mjs` compiles answer-key-free worker units from one matrix and binds declared model and execution policy to deterministic score receipts.

GitHub Action dependencies have one reviewed lock at `.github/actions-lock.json`. The action-pin checker requires exact lowercase commit SHAs, full semantic-version annotations, complete review metadata, and `.node-version` as the only setup-node runtime authority. It scans repository workflows, shipped examples, reusable workflows, and the metadata of reachable local composite actions with physical-path deduplication. Unsupported YAML forms, mutable or unlisted actions, unsafe local paths, and policy drift fail closed.

The run contract turns multi-agent work into a bounded artifact. It validates routing floors, dependency order, parallel write separation, retry limits, acceptance ownership, optional per-unit token budgets, and final proof. Version 2 binds exact context and version 3 adds the host/runtime boundary. Version 4 requires a frontier lead, lower-tier operatives, a real disjoint parallel wave, independent validation, and nonempty operative evidence. A valid calibration block admits a strong lead for assess-only calibration arms (b) and (c) instead. It requires read-mode units and artifacts outside every scope, and units may run at the lead tier but never above it. It rejects a lead model that also serves the frontier rung, because that arm cannot measure a strong-versus-frontier gap. Every new substantive run uses version 4; versions 1 through 3 remain readable only for replay. Capability initialization rejects Git-visible or linked output before writing raw provenance. Capability and receipt paths cannot collide portably or resolve to one physical file. Stable-prefix sources must be regular stage-0 files without linked components. Runtime replay accepts only exact SHA-1 or SHA-256 Git object IDs, and the chain retains no raw host labels. The runtime engine checkpoints, resumes, and replans through one locked hash chain while reusing contract, ledger, partial acceptance, bundle, Atlas, and handoff authorities. Runtime status exposes pending work, unresolved criteria, drift, and observable token-budget overruns without treating a checkpoint as completion.

The dispatch journal is the runtime authority for actor and state continuity. It accepts only legal transitions, requires dependencies to complete before activation, keeps one recorded host or session actor identity across a unit attempt, and prevents one actor from satisfying independent discovery and validation roles. Under a version 4 contract, `add` keys each row by its contract unit, requires an actor, and binds the journal to the contract run. Checkpoint, replan, resume, and verify reconcile in flight: they reject permanent journal violations and admit planned units that have not reported. Finalization stays strict. Actor identifiers are auditable runtime records, not cryptographic identity attestations.

`attack-chain-graph.mjs` compiles security hypotheses, primitives, collisions, blocked terminals, resumptions, and validated impact into one graph. It proves artifact confinement and hashes, exact glob intersections, unique family launches, anti-convergence history, distinct implementation-layer receipts, realistic success conditions, and independent validation. Final mode rejects every open or off-chain node; in-progress mode exposes and ranks only graph-reachable open resumptions.

The cost estimator is a planning advisory, not accounting evidence. It projects dispatch shape from finalized historical runs. When an operator supplies a dated price snapshot, it separately attributes observed runtime tokens and a subtotal to receipt-bound models. Missing observations remain unknown, and the subtotal is never presented as a provider invoice.

The context compiler separates reusable structural indexing from unit context. A snapshot hashes visible Git state and generator identities, then caches the repository map, import graph, and optional Atlas report by content address. It preserves Unicode rename and copy destinations, canonicalizes aliased roots before symlink containment checks, and parses live Atlas freshness output. A bundle selects scoped files, import neighbors, visible changes, and fresh Atlas excerpts. Its worker view preserves indexed metadata and graph edges in stable columns while binding the canonical bundle. Reported byte counts cover final serialized payloads. Empty scope, broad scope, and byte overflow fail explicitly instead of producing misleading or truncated context.

Documentation tooling discovers one `<hub>/98 System/DOCS_MANIFEST.json` rather than assuming a repository name. It hashes declared source and target records, rejects source globs that match no repository file, plans only affected domains, and routes citation checks through every manifest-owned Markdown target. A plan may tolerate digest drift but rejects structural manifest errors; citation parsing accepts bracketed paths and interior directory spaces without swallowing ordinary prose. Vault conformance limits manifest frontmatter exemptions to published reference bands, so an arbitrary manifest entry cannot exempt working notes. Link validation covers Obsidian wikilinks and Markdown links. It rejects hub-internal directory targets because they do not identify notes, and local Markdown fragments that do not identify headings. Directory links outside the hub remain valid repository references. `sync-vendored` and both renderers remain derived-output boundaries; the pre-commit hook is a convenience layer and CI is the final backstop.

Structural lint check 24 keeps shipped text resolvable outside a code-ops checkout. `sync-vendored.mjs` copies each declared hub technique page into `plugins/<plugin>/reference/` beside the runtime scripts, and lint holds every copy to byte parity and rejects undeclared files. Both scripts import the vendored manifest as a namespace, so a manifest without the reference exports still loads. A pattern scan then reads the canonical plugins and, when present, both host projections. It reports hub paths, repository-root commands, and citations of files the plugin does not bundle, unless a code-ops repository marker shares the Markdown block or the code line. It also resolves every plugin-root path against the files that plugin ships. Source comments, CHANGELOGs, and the reference copies are not scanned; parity already governs the copies.

Manifest v2 adds explicit run tracking, permanent record collections, and bounded legacy paths. Inventory v3 appends one authority-batch chain for exact-once membership and provenance. Adoption batches require `adopted` objects. Native batches require `native` objects and prove the exact path had no history through the source and first appeared with its batch. Every non-genesis batch re-derives its complete predecessor binding. Only an observed committed v2 predecessor permits migration to preserve provenance-less legacy artifacts. The separate curation ledger owns status and supersession. The records engine uses exact-case Git-index paths and regular-file blobs for deterministic IDs. It resolves citation suffixes, pins mutable evidence by SHA-256, and treats Git object IDs as regenerable locators.

A bounded snapshot batches stage-0 and historical blobs, rejects a current governed blob above 32 MiB, and hashes binary payloads by Git-framed sizes. Historical blobs above the batch ceiling fall back to individual reads under the existing 64 MiB Git process bound. Literal HEAD-tree and receipt-source lookups are also batched. Reachable-object recovery reads bounded content batches with a compatibility fallback. Content-aware Git diffs detect semantic worktree divergence. Generated authorities stay under `98 System/Records/`. Atomic writes reject linked path components before replacement. The ordinary link gate remains separate.

Adoption history starts from each current immutable path and follows its rename lineage. Per-path queries own rename evidence. Bounded exact-path batches add non-rename events, including first-parent merge diffs. Bounded object batches then hash the discovered history without one Git process per blob. Explicit path and event ceilings also bound the work. The reviewed current exact-path admission becomes the identity anchor. Earlier lineages still determine readiness.

One command reuses its repository completeness, object format, and committed manifest snapshot. The cache never crosses an operation or replaces either manifest transaction guard.

Genesis review binds exact history and canonical Git-index bytes. Incremental review also binds existing generated authority and the prior batch head. Complete-history checks require exact batch candidate coverage, exact-once collection coverage, canonical current bytes, classification, risk consistency, rationale coverage, and non-increasing risk counts.

All authority writers share a clone-wide lock under Git's common directory. Writers prove token plus directory identity before authority writes and release. Stale recovery quarantines the judged directory and refuses a replacement lease. Ordinary cleanup errors preserve durable success; ownership loss exits 3 with a do-not-retry result. Optimistic bindings reject stale work from other clones. Commands validate existing evidence before `pending-admission`, build in memory, replace atomically, verify the written state, and roll back on failure. Protected repository review remains the trust root.

The traceless scanner distinguishes Unicode emoji presentation from layout glyphs. Its optional single-file dash baseline reads the same tracked path at an ancestor commit and measures only introduced density. The ordinary absolute threshold remains the default, arbitrary baseline files are rejected, and every hard tell still reads the full current text.

The scanner's `--command` mode lexes a shell command into simple commands, including quotes, ANSI-C strings, command substitutions, and heredocs. Only `git commit`, `gh pr create|edit|merge`, and `gh api` segments contribute published values, so a phrase in another segment or a non-message argument stays clean. The raw command is still scanned, and the verdict is the union. The `enforce-traceless` hook and its OpenCode port both use this mode; they block on any nonzero scanner exit and fail open only when the scanner cannot spawn, because the PR traceless CI step is fail closed.

Measurement has a host-qualified receipt path. Claude deduplicates transcript usage and nested
subagents. Codex follows peer rollout `parent_thread_id` links. Installed Grok 1.0.13
normalizes cumulative usage from `updates.jsonl` and records its unavailable ladder arm false.
OpenCode has no transcript callback. `context-audit.mjs` is the sanitized CLI, and the
`SessionEnd` hook is the supported-host ledger writer. None touches the model, network, or
repository tree. Grouped receipts are descriptive until a pre-registered matched control
supports a causal claim.

Register citations are confined by what they resolve to, not only by their text. `citation-lib.mjs` flags a backslash or drive-letter prefix directly at `scripts/citation-lib.mjs:137`, restores a dropped forward-slash prefix from a bounded window that fails closed when a path-shaped run fills it, and requires a cited file's real path to stay under the root's real path. `revalidate-register.mjs` and `check-handoff.mjs` both import it at `scripts/check-handoff.mjs:61`, so the register gate and the handoff gate rank a pointer FRESH, MOVED, DRIFTED, GONE, or AMBIGUOUS under one rule. The handoff gate also requires the six sections that answer an operator's resume questions, a verbatim `Request:` line, a confidence label on every Key findings bullet, and an 8 KB ceiling; its `--consume` flag writes `HANDOFF.consumed` only after every check passes, which retires that handoff from the routing card's pickup line. `integrate-branch.mjs` runs the per-change bump, host renders, manifest sync, and atlas report, then selects `validate.yml` steps from the changed paths; stamping and changelog text stay manual.

The narration scanner reports mannered prose (metaphor standing in for a literal phrase) as an advisory category beside filler.

Command output has a compressor of its own. `digest.mjs` spawns a command, keeps the raw bytes in a home-directory receipt store, and prints a view compressed by output shape rather than by command name. Nine detectors cover diffs, diagnostics, test runs, stack traces, logs, tables, listings, JSON, and an unrecognized fallback that passes through under a line cap. The compression is loss-bounded by contract: the must-keep line set is fixed before any stage runs, and no stage may drop or rewrite a line in it. Every elision prints the exact command that recovers it, and the child's exit code always becomes the digest's. A `--cwd` names the directory the command runs in, so a caller that would have written `cd <dir> && <cmd>` keeps the no-shell contract. The `digest-rewrite.mjs` hook now reaches it from a `PreToolUse` Bash stage, but only in a repository that set `CODE_OPS_DIGEST`; everywhere else it still runs only when an operator invokes it.

One entrypoint now stands over the canonical scripts. `co.mjs` resolves a domain and verb to a sibling script, rewrites the argument list, and imports it. It migrates no logic: every script keeps its own flags, its own exit codes, and its existing direct path. `cli-lib.mjs` ships beside it and holds the flag parser, usage and exit helpers, git wrapper, and file walker that the scripts had each rewritten. The `scan` domain is the first consumer: its seven scripts parse through `parseFlags` and report a caller error through `parseOrDie`, with every flag, exit code, and message preserved. The skills that ran those scripts by path now invoke `co.mjs scan <verb>`, and the structural linter resolves a façade reference through the verb table so it carries the same bundling requirement.

`skim.mjs` is the read-side economy tool: it prints a file's outline with line numbers, spans, and an announced truncation line, so a reader requests a range through `--range` instead of taking the whole file, and outline mode itself prints names and headings rather than bodies.

Atlas freshness now answers at two granularities. The section digest still answers whether anything in scope moved. A claim answers whether one cited line still carries the substring the prose was written against, classified by the register checker rather than a second mechanism of its own, at `scripts/atlas-check.mjs:306`. The two verdicts are independent, and both directions carry information. A fresh digest with a drifted claim is a lead, not a proof. A stale digest whose claims all hold lets a reader keep the cited sentences and re-derive only the rest. The claim gate is opt-in and separate from the section gate. The scope suggestion reads the symbol index's importer edges at depth one and writes nothing.
The symbol primitives have one owner. `symbol-lib.mjs` holds the definition rules at `scripts/symbol-lib.mjs:45` and the import extraction, and `repo-map.mjs`, `import-graph.mjs`, `skim.mjs`, and `context-query.mjs` all read from it at `scripts/context-query.mjs:54`, so the map, the graph, the outline, and the index cannot disagree. An import edge carries `relative` and `dynamic` beside its specifier and target, which is how the graph keeps separating an unresolved path in the tree from a package name and keeps noting a non-literal `import(...)` rather than dropping it.
`dispatch-ledger.mjs update --status reported` can gate an operative report file before the row turns terminal. With `--report`, a missing, empty, or whitespace-only file is refused. With `--sections`, a named heading that is absent or holds no body outside subheadings is refused, and headings inside code fences do not count. A refusal writes neither the ledger nor its journal. The flag is optional, and evidence quality stays with the lead.
