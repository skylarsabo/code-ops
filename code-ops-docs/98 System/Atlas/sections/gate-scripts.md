# Gate scripts and hooks

Charter: repository gates, renderers, orchestration compilers, and hook behavior. Excludes workflow scheduling and eval fixtures.

The default posture is fail closed. Usage errors, malformed configuration, drifted generated output, untrusted documentation records, and invalid receipts fail. Process-risk advisories remain explicit exceptions. Atlas ambiguity is fail-safe: the checker calls a section stale rather than treating uncertain judgment as current. Digest-backed sections bind exact scopes, the staged index, and the index-to-worktree delta; commit pins remain diagnostic and legacy-compatible.

Model judgment no longer depends on repository-hosted review workflows. `local-review-gate.mjs` binds a clean feature branch, base, HEAD, binary diff, changed paths, two independent report identities, and a hash-chained receipt set. A shared index guard rejects assume-unchanged, skip-worktree, and submodule ambiguity before either local review or judgment planning reads worktree bytes. Publication verifies live remote base and feature refs and binds the destination repository to that same remote. `judgment-evals.mjs` compiles answer-key-free worker units from one matrix and binds declared model and execution policy to deterministic score receipts.

GitHub Action dependencies have one reviewed lock at `.github/actions-lock.json`. The action-pin checker requires exact lowercase commit SHAs, full semantic-version annotations, complete review metadata, and `.node-version` as the only setup-node runtime authority. It scans repository workflows, shipped examples, reusable workflows, and the metadata of reachable local composite actions with physical-path deduplication. Unsupported YAML forms, mutable or unlisted actions, unsafe local paths, and policy drift fail closed.

The run contract turns multi-agent work into a bounded artifact. It validates routing floors, dependency order, parallel write separation, retry limits, acceptance ownership, and final proof. Version 2 binds the contract to an exact context snapshot and rejects drift, hidden Git-index state, or an untracked-policy mismatch before work proceeds. Version 3 adds a host-capability receipt, ordered stable prompt prefix, explicit cache/compaction/editing/memory policy, and a runtime receipt path. Capability and receipt paths cannot collide portably or resolve to one physical file. Stable-prefix sources must be regular stage-0 files without linked components. Runtime replay accepts only exact SHA-1 or SHA-256 Git object IDs, and the chain retains no raw host labels. The runtime engine checkpoints, resumes, and replans through one locked hash chain while reusing contract, ledger, acceptance, bundle, Atlas, and handoff authorities.

The cost estimator is a planning advisory, not accounting evidence. It projects a proposed dispatch from historical ledger results; completed-run cost remains derived from final-result records at the stable result schema version.

The context compiler separates reusable structural indexing from unit context. A snapshot hashes visible Git state and generator identities, then caches the repository map, import graph, and optional Atlas report by content address. It preserves Unicode rename and copy destinations, canonicalizes aliased roots before symlink containment checks, and parses live Atlas freshness output. A bundle selects scoped files, import neighbors, visible changes, and fresh Atlas excerpts. Its reported byte count converges on the final serialized payload. An empty scope, broad scope, and byte overflow each fail with an explicit marker instead of producing a misleading ready bundle or silently truncating context.

Documentation tooling discovers one `<hub>/98 System/DOCS_MANIFEST.json` rather than assuming a repository name. It hashes declared source and target records, rejects source globs that match no repository file, plans only affected domains, and routes citation checks through every manifest-owned Markdown target. A plan may tolerate digest drift but rejects structural manifest errors; citation parsing accepts bracketed paths and interior directory spaces without swallowing ordinary prose. Vault conformance limits manifest frontmatter exemptions to published reference bands, so an arbitrary manifest entry cannot exempt working notes. Link validation covers Obsidian wikilinks and Markdown links. It rejects hub-internal directory targets because they do not identify notes, and local Markdown fragments that do not identify headings. Directory links outside the hub remain valid repository references. `sync-vendored` and both renderers remain derived-output boundaries; the pre-commit hook is a convenience layer and CI is the final backstop.

Manifest v2 adds explicit run tracking, permanent record collections, and bounded legacy paths. Inventory v3 appends one authority-batch chain for exact-once membership and provenance. Adoption batches require `adopted` objects. Native batches require `native` objects and prove the exact path had no history through the source and first appeared with its batch. Every non-genesis batch re-derives its complete predecessor binding. Only an observed committed v2 predecessor permits migration to preserve provenance-less legacy artifacts. The separate curation ledger owns status and supersession. The records engine uses exact-case Git-index paths and regular-file blobs for deterministic IDs. It resolves citation suffixes, pins mutable evidence by SHA-256, and treats Git object IDs as regenerable locators.

A bounded snapshot batches stage-0 and historical blobs, rejects a current governed blob above 32 MiB, and hashes binary payloads by Git-framed sizes. Historical blobs above the batch ceiling fall back to individual reads under the existing 64 MiB Git process bound. Literal HEAD-tree and receipt-source lookups are also batched. Reachable-object recovery reads bounded content batches with a compatibility fallback. Content-aware Git diffs detect semantic worktree divergence. Generated authorities stay under `98 System/Records/`. Atomic writes reject linked path components before replacement. The ordinary link gate remains separate.

Adoption history starts from each current immutable path and follows its rename lineage. Per-path queries own rename evidence. Bounded exact-path batches add non-rename events, including first-parent merge diffs. Bounded object batches then hash the discovered history without one Git process per blob. Explicit path and event ceilings also bound the work. The reviewed current exact-path admission becomes the identity anchor. Earlier lineages still determine readiness.

One command reuses its repository completeness, object format, and committed manifest snapshot. The cache never crosses an operation or replaces either manifest transaction guard.

Genesis review binds exact history and canonical Git-index bytes. Incremental review also binds existing generated authority and the prior batch head. Complete-history checks require exact batch candidate coverage, exact-once collection coverage, canonical current bytes, classification, risk consistency, rationale coverage, and non-increasing risk counts.

All authority writers share a clone-wide lock under Git's common directory. Writers prove token plus directory identity before authority writes and release. Stale recovery quarantines the judged directory and refuses a replacement lease. Ordinary cleanup errors preserve durable success; ownership loss exits 3 with a do-not-retry result. Optimistic bindings reject stale work from other clones. Commands validate existing evidence before `pending-admission`, build in memory, replace atomically, verify the written state, and roll back on failure. Protected repository review remains the trust root.

The traceless scanner distinguishes Unicode emoji presentation from layout glyphs. Its optional single-file dash baseline reads the same tracked path at an ancestor commit and measures only introduced density. The ordinary absolute threshold remains the default, arbitrary baseline files are rejected, and every hard tell still reads the full current text.
