# Documentation doctrine

Charter: substantive authored records in the documentation hub and the scripts that validate them. Excludes Atlas bookkeeping, run scratch, and generated host output.

`code-ops-docs/` is the sole substantive hub. Its `<hub>/98 System/DOCS_MANIFEST.json` is the only topic-to-target and topic-to-source registry. It maps architecture, contracts, data, standards, API reference, delivery, infrastructure, operations, experience, guides, and Atlas records to canonical Markdown. A `not-applicable` domain needs concrete evidence. Code, workflows, schemas, and configuration remain evidence, not competing prose authorities.

Vault standard v4 separated authority from location, and v5 keeps that split. Manifest-v2 record collections may preserve immutable evidence at permanent historical paths, while generated inventory, citations, curation, and semantic indexes stay beneath the hub's `98 System/Records/`. A collection remains open while each admission remains irreversible. Inventory v3 records exact-once membership and enforces provenance through one authority-batch chain. Adoption batches carry adopted objects. Native batches prove exact-path history and their introduction commit. Each non-genesis batch binds its immediate predecessor state. Only an observed inventory-v2 predecessor permits migration to preserve provenance-less legacy artifacts. Inventory v1 remains readable but cannot use incremental admission or enter the batch chain. The separate curation ledger moves current authority through status and supersession. Manifest v1 remains valid for v3 and collection-free v4 repositories. Standard v5 accepts manifest v1, v2, or v3, and this repository runs standard v5 on manifest v2.

Standard v5 splits the hub into two layers. The state layer is rewritten in place under declared word budgets, and the history layer is append-only. A four-clause register invariant binds decisions, and clause 4 compares `<domain>/<subject>` topic keys (code-ops-docs/Standard.md:66, code-ops-docs/Standard.md:73). A decision is `in-force`, `amended`, `superseded`, or `historical`. D-004 lets a collection root move through a `relocate-root` curation event while admitted bytes stay irreversible. The record tooling now records that event through `records.mjs relocate-root`, and a root change without it fails history checks (code-ops-docs/Standard.md:121). `render --register` generates `20 Decisions/REGISTER.md` from the collections, and `CONTRACTS.md` states the record meaning, typed curation, intake and seal, root relocation, and register contracts.

`docs-manifest.mjs` discovers a generic hub by manifest location, validates content and source digests, rejects source globs with no repository evidence, and creates a delta-based plan. `docs-extract.mjs` invokes the sibling validator from its own installed directory. The extractor dispatches only affected domains, and a fresh digest proves only declared coverage.

Citation validation reads current and not-applicable manifest targets instead of a hard-coded list. Vault conformance protects working-note structure while the manifest owns reference-target completeness. The vault check skips notes git ignores, found by one `git ls-files --others --ignored` call (`scripts/check-vault-standard.mjs:190`), so run scratch never fails it; a tracked note is always checked. Only manifest targets in published reference bands, and record bytes under a manifest collection root inside the hub, receive the frontmatter exemption; the rendered register carries its own frontmatter. Markdown and Obsidian wikilinks both fail when their targets are absent, case-unsafe, or ambiguous; code examples remain inert. The guide domain lives directly at `70 Guides/`, not under a duplicate nesting level. ADR 0001 preserves the historical handbook placement decision as superseded; ADR 0002 is the current migration decision. The legacy scratch locations remain ignored for compatibility, not as alternative documentation homes.

Under manifest v3, a draft's status comes from `drafts.statuses` alone. A `superseded` note links to its successor, and a draft marked PROMOTED or SUPERSEDED fails until its status says so. `check-vault-standard.mjs --render` generates `10 Design/INDEX.md` and `98 System/TRIAGE.md`, and nobody edits either by hand. The triage queue lists stale drafts and unsourced synthesis pages without failing. A page that declares `sources:` records a `sourceDigest:`, and `--stamp` refreshes it after a review. A v1 or v2 vault sees none of these rules until it upgrades its manifest. `co docs gate` runs the docs checks and ratchets them through `98 System/GATE_BASELINE.jsonl`, which a person never edits by hand.

Linked hub collections expose explicit Markdown index notes; bare directories are not navigation targets. Local Markdown fragments name real headings rather than decorative labels. The house writing standard remains one authority in `40 Engineering/Techniques/writing-standard.md`, with mechanically pinned core clauses where host packages require local copies. The house code standard follows the same shape: `40 Engineering/Techniques/code-standard.md` is its single source, and `ENGINEERING_STANDARDS.md` points its performance and size sections there.

Six technique pages are also execution specs: artifact grammars, atlas, calibration protocol, fleet standard, subagent trade-offs, and vault standard. Each ships byte-identical inside the plugins whose skills run against it, so the hub page stays the single source and an edit there must be re-synced before lint passes. Because those copies reach other repositories, the atlas page places the atlas at `<repo>-docs/98 System/Atlas/` and falls back to `<repo-root>/atlas/` only when a repository has no `<repo>-docs/` hub.

Atlas doctrine distinguishes a portable content digest from its diagnostic commit stamp. The default workflow stages scoped changes before stamping. Historical `--at` stamps intentionally remain commit-only, and legacy manifests migrate on their next verified refresh.

This section deliberately scopes substantive domain folders and documentation scripts rather than the hub root. Manifest digest updates and Atlas bookkeeping therefore do not invalidate the record by themselves. A source or canonical-document change still does.

One exact repository snapshot still serves each run. Documentation extraction contributes only affected collection indexes and inventories. Agents fetch a record body by permanent ID only when a domain needs it, so evidence volume does not become default context volume.

ADR 0006 defines the receipted long-horizon runtime: stable prompt prefixes are bounded, regular, unlinked, and reusable, while mutable work advances through checkpoints and compaction summaries. Its authority paths are portable and non-aliased, receipt heads use exact Git object IDs, and receipt metrics omit raw host provenance. ADR 0007 places model judgment before PR creation. Its ignored reports and receipts remain operational evidence; authored architecture, contracts, delivery, and operations references describe the durable policy. Hidden index state invalidates context snapshots, local review, and judgment planning before worktree bytes are trusted. Judgment output paths reject linked components and physical authority aliases before a write.

Admission review has two time domains. Before admission, any bound Git, manifest, candidate, generated-authority, or batch-head change invalidates the plan. Review plans stay at repository-relative ignored paths. The reviewed current path anchors identity, and the matching content commit supplies the citation baseline. After admission, locator-only repair cannot change authority membership or increase reviewed risk counts. Checkout-only transformations never change evidence identity.

The hub now owns a measurements reference under `55 Operations/`, registered as its own manifest domain over the transcript library, the audit CLI, the receipt hook, and their eval. Its rows come from local host transcripts and receipts only, and a cross-project row counts threads without naming or quoting the repositories behind them. The design note under `10 Design/` that motivates them proposes and never binds.

Provider doctrine defines one portable outcome across Claude, Codex, installed Grok, and OpenCode while preserving host-native mechanics. Capability matrices name unsupported callbacks explicitly, and measurement prose separates synthetic adapter proof, installed-runtime observation, and live external-turn evidence.

The writing standard defines mannered prose and a formatting rule. Context hygiene keeps ordinary turns append-only, uses turn-scoped reminders, and requires durable checkpoints before a host-managed compaction; cache and reconstruction costs depend on the active surface and must be measured ([context hygiene](../../../40%20Engineering/Techniques/context-hygiene.md#compact-deliberately); checkpoint rule at plugins/code-ops-suite/skills/handoff/SKILL.md:71). Global standards guidance keeps stable provider-neutral doctrine shared while allowing small, explicit Claude and Codex host deltas. Repository contracts retain only local facts, commands, gates, and exceptions.

Routing guidance now selects role, tier, and effort from the assigned work while retaining declared quality floors. Dispatch guidance distinguishes explicit host-agent budget binding, the brief's `Round budget:` line, and legacy fallback. The brief template adds a `Report cap:` field and a `Wide-surface reason:` line. The dispatch guard denies a wide or unnamed agent type without that line, denies a suite-agent brief that lacks a field the agent's `Brief requires:` line lists, stops an unbound operative at 1.5 times its budget, rounded down and at least one call past it, and denies new dispatches past the context ceiling, 300,000 tokens by default and 200,000 on Grok, until a handoff assessment runs. It also adds a warn-only collision note that names live peers on an edited path or a git pull, merge, rebase, or push; the contracts reference calls it the fifth behavior. The sixth denies an edit under a `removed` legacy root and names the forwarded location, and the handoff card adds a history read notice when a Read, Grep, or shell call opens a decision record that is not in force, each with its own off switch. The contracts and infrastructure references document the advisory `SubagentStop` report hook and the `PreToolUse` peer guard with their off switches, the presence board and its writers (the contracts reference, section "Presence board"), and the routing card's operator-shell line with its `CODE_OPS_OPERATOR_SHELL` override. The contracts reference also owns the change feed (event kinds, store bounds, writers, delivery, and the `CODE_OPS_FEED` switch) and the `program overlap:` block that `run open --program` and `resume` print, and the infrastructure reference lists both stores and the per-host coverage. Measurements record the receipt `skills` count and the per-event hook latency baseline and the after-PR figures. Measurements pre-register the round stop and the context ceiling as SPECULATIVE, and a dated amendment records the move from the twice-budget stop to 1.5 times. Worker views may omit only sections the context contract does not require; omission remains explicit (scripts/run-contract.mjs:115, scripts/context-bundle.mjs:139).

`CONTRACTS.md` also holds the agent state machine: each entity's states and store, and each transition with its guard, writer, and build status. The long-horizon guidance now makes lifecycle assessment explicit: continue a bounded coherent task, compact only after durable checkpointing and through a callable host capability, or hand off only to start new work, to load updated code-ops plugins in a clean session, or after a host change or failed compaction (DEC-76). A context band, handoff file, or post-compaction restore does not itself perform a transition, preserve a summary, or broaden authority (plugins/code-ops-suite/skills/handoff/SKILL.md:73, plugins/code-ops-suite/hooks/handoff-card.mjs:12). The contracts reference documents the Grok-only 200,000-token handoff point, the marker fields `point`, `fired`, `prompts`, and `until`, and the `Continue-until:` bound. It also documents the hashed `Dirty:` record and the `same-tree` rule that every recorded hash must still match. Ledger grammar 2 is documented there too: its opt-in line, checks 11 to 19, the grammar-2 draft, and `co program archive`. It also documents the agent ledger with `co agents pending`, the `draft` refusal while agents are unreported, `co agents settle`, the `SessionEnd` ended marker, `co burndown`, and the routing card's `TASKS.md` and `Pending agents:` lists; `INFRASTRUCTURE.md` lists the hook among its fourteen commands on eight events (code-ops-docs/50 Platform/INFRASTRUCTURE.md:40). The contracts reference also owns the `PreCompact` snapshot hook `compact-snapshot.mjs`, its budgets, and the compact card's `Snapshot fresh`, `STALE`, and `absent` lines in place of the `TASKS.md` and `Pending agents:` lists alone (code-ops-docs/35 Contracts and Data/CONTRACTS.md:253, code-ops-docs/35 Contracts and Data/CONTRACTS.md:299). It documents the checkpoint-first card text and the `co handoff draft` peer warning and running-work seed (code-ops-docs/35 Contracts and Data/CONTRACTS.md:733, code-ops-docs/35 Contracts and Data/CONTRACTS.md:865). `INFRASTRUCTURE.md` lists the `CODE_OPS_COMPACT_SNAPSHOT` off switch (code-ops-docs/50 Platform/INFRASTRUCTURE.md:74). Measurements pre-register the move from about 350,000 to about 225,000 tokens as a modeled value, not a measurement ([handoff point](../../../55%20Operations/MEASUREMENTS.md#pre-registered-handoff-point)). A 2026-09-30 amendment (DEC-73) retires that point on Claude and Codex in favour of auto-compaction. Measurements record the policy as an advisory rather than evidence of a handoff, compaction, delivery, or cost outcome ([measurement amendment](../../../55%20Operations/MEASUREMENTS.md#pre-registered-handoff-card-threshold); invocation evidence at plugins/code-ops-suite/hooks/session-receipt.mjs:152).
